# regiondiff/ — the regional-variant reconstruction pipeline

Goal: for every function that DIFFERS between the matched base
(`NFS4-B-USA.EXE == nfs4-f.exe`, the main project) and the six retail
regionals, produce a source-level reconstruction that passes the regional
gate — the same attempt→gate→board loop as the main project, against the
regional oracles.

Corpus provenance: `C:\Temp\nfs4-clean\Binaries\regionrecon\` (generated by
`regionrecon.py`; regeneration recipe in [CORPUS_README.md](CORPUS_README.md)).

## Layout

| path | what |
|---|---|
| `MANIFEST.tsv` | the work plan — one row per (function, byte-variant group); 232 rows / 218 fns. Regen: `python regiondiff/tools/gen_manifest.py` |
| `REGION_PROGRESS.txt` | the board. Regen: `python regiondiff/tools/update_region_progress.py` |
| `variants.tsv` | relocation-masked cross-region dedup (207 fns = one variant everywhere, 11 with real inter-region splits) |
| `oracles/<REGION>/<fn>.s` | LINKED regional slice per differing fn (m2c dialect, jump tables resolved) + `INDEX.tsv` (class/VAs/callers/strings) |
| `m2c/<REGION>/<fn>.c` | m2c fork decompile of each slice — the reference body for what the region changed |
| `recon/<REGION>/<unit>.cpp` | YOUR candidates: a copy of the owning base TU with the regional edits |
| `tools/verify_region.py` | the gate |

Regions: `NFS4-R-USA / -AU / -FR-DE / -JPN / -UK-ES-IT / -UK-SW`
(short forms `USA`, `AU`, … accepted by the tools).

## The gate

```
python regiondiff/tools/verify_region.py <REGION> <candidate> <fn[,fn...]> [--lane-as recon/<unit>.<ext>]
```

Compiles the candidate through the REAL `tools/build.py` pipeline (per-TU
lanes, per-fn splices; `--lane-as` inherits the base TU's lane and compiles
from a temp copy beside the base TU so sibling `#include "..."` resolve —
it defaults from the manifest, pass it explicitly when in doubt), then
diffs each fn against `oracles/<REGION>/<fn>.s`.

**REGION-PASS semantics.** The oracle is a linked slice of a DIFFERENT
memory layout with no relocation info, so the gate aligns on
mnemonic+registers and masks, on both sides, exactly the fields our own
object marks as relocations (HI16/LO16/GPREL16/26). A REGION-PASS proves
opcodes, registers, schedule and every non-reloc immediate match the
regional build. It is NOT byte authority (a wrong constant offset into a
relocated symbol is invisible — same soundness gap as the base gate's
LO16-zeroing; byte authority would need a per-region link map).

## Agent workflow (one manifest row)

0. **READ FIRST (mandatory):** fully read
   `C:\Users\Vyacheslav\.claude\projects\C--Temp-claud\memory\reference_mips_isa_asm.md`
   and `...\memory\reference_psx_cpp_reconstruction_methodology.md`, then
   `reference_asm_pattern_catalog.md` for symptom→fix lookups.
1. Pick a TODO row from `REGION_PROGRESS.txt` / `MANIFEST.tsv`.
2. **Seed** the candidate at the row's `candidate` path — ⚠️ **NEVER
   overwrite an existing candidate** (it may hold other rows' sealed
   regional edits; check first, and add your rows' edits to it instead):
   - CHANGED: copy the base TU `recon/<unit>.<ext>` verbatim (the base body
     is the sealed starting point; usually only the target fns change).
   - REGION-ONLY: new standalone TU seeded from `m2c/<REGION>/<fn>.c`.
   A candidate file may host every variant fn of its (unit, region) pair.
3. **Measure first**: gate the UNEDITED seed — the diff IS the regional
   change. Read it next to `m2c/<REGION>/<fn>.c` and sibling regions'
   slices.
4. **Edit** the target fns to reproduce the regional codegen. Source-level
   C/C++ only.
5. **Gate** until REGION-PASS; then run
   `python regiondiff/tools/update_region_progress.py` and check no other
   row regressed.

## Rules (same bar as the main project)

- Source-level match only: **no volatile, no asm** — the only exception is
  cop0 and gte macro blocks. **No post-compilation instruction moves, no
  seals.** No `register ... asm("$N")` pins.
- **Do not edit `tools/*.py` or `regiondiff/tools/*.py`.**
- **Do not edit the base tree** (`recon/**`, `src/**`, `asm/**`,
  `configs/**`) from regional work — regional candidates live ONLY under
  `regiondiff/recon/`. If a base file you need is in use by the user, work
  on a copy.
- Preserve user edits; use reference decomp idioms/macros where helpful
  (`C:\Temp\ps1-decomp-refs`, `C:\Temp\sh-decomp`, …).
- Naming: CHANGED fns keep their base ground-truth names. REGION-ONLY fns
  stay `func_<region_va>`. An unidentified region-layout global gets a
  mechanical name (`RDAT_<reprRegionVA>`) + an `[INFERRED]`/identity-TBD
  comment — no invented semantic names (§8.3 no-auto-naming).
- Regional VAs are the REGION's layout: never look base symbols up by a
  regional address (identify via callers/strings/`INDEX.tsv`/cross-region
  compare instead).

## Why this corpus matters

The 188 CHANGED rows are cross-version oracles: the same source compiled
by the retail (later) link — different lib vintages (sprintf/PAD*/
FntPrint/CD_Read/main all CHANGED), retail-only guards, and per-region
logic (language menus, display timing, memcard formats). Sealing them both
documents the retail deltas and fingerprints the retail toolchain rungs
(e.g. FntPrint CHANGED while FntFlush stayed LO16 — evidence toward the
FntFlush vendor-identity certificate).

## Corpus maintenance tools (2026-09-02)

- `tools/audit_lo16.py` — re-checks every LO16/RELOC row with a PRECISE
  reloc mask from the base oracle's own `%hi/%lo/%gp_rel` markers; found
  105 HIDDEN-CHANGED fns the LOOSE fingerprint missed (report:
  `AUDIT_LO16.txt`). Most are the retail string-table +1 shift; some are
  real gameplay constants.
- `tools/extend_corpus.py` — promotes audit findings into the corpus
  (slices + INDEX rows + variants groups by exact delta signature).
- `tools/gen_symmap.py` — derives a PER-REGION data-symbol address map
  (`oracles/<R>/symmap.tsv`, ~2500 symbols/region, consensus-voted from
  the linked images at oracle-marked reloc sites). The foundation for
  byte-authority (brdist-R) and a future regional DATA audit.
- Upstream `regionrecon.py` (in C:\Temp
fs4-clean\Binaries) carries the
  W85 fixes: $sp displacements excluded from jtbl symbolization, trailing
  zero-word trim. The audit-vs-oracle size check catches name-shift and
  boundary over-runs on regeneration.
- `tools/audit_data.py` — the regional DATA audit (built on symmap.tsv):
  per-symbol word compare with pointer words verified THROUGH the
  text+data maps (relocation never false-positives; a retargeted pointer
  IS caught). Text symbols and double-sided size gaps filtered. Report:
  `AUDIT_DATA.txt` + per-symbol dumps under `data/<REGION>/`.
  18-27 genuinely changed data symbols per region (packed text-id tables
  like TextLocations 80 words, menu SelectLists, vtable slots with
  unresolved pointers = likely retail-added virtuals, one-word tuning
  constants). Data rows are NOT yet gated rows — reconstruction of these
  means editing the regional candidates' initializers; wiring them into a
  gate is the remaining piece of backlog item 10.
