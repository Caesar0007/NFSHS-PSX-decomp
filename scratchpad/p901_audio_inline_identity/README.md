## What the native records actually establish

`native_identity_receipt.json`, regenerated by read-only `audit.py`, accounts for
**all 20 literal CAudioList strings in the raw 7,881,225-byte NFS4.SYM** inside
**13 corresponding dump records**. Seven typedef records contain the classname
twice (tag and name), explaining the 20-versus-13 counts. There is no additional
literal classname occurrence hidden by this dump conversion.

The 13 records comprise two STRTAGs, two EOS records, seven typedefs, one EXT
global record, and one REG `this` record. **None is a named CAudioList function
record.** No CAudioList method symbol occurs in the linker MAP either. This is a
bounded census of these artifacts, not a claim that no source can ever be found.

Both class definitions agree exactly:

| Record range | Field/type/offset |
|---|---|
| audedit 1a31ab..1a321e | CAudioList, size16 |
| audiotrk 1b6dce..1b6e41 | CAudioList, size16 |
| both | int id_ at0, int numElements_ at4, int slice_ at8, int versionNumber_ at12 |

The audedit-owned EXT pointer `gGameAudioList`, record1a8edf, is at8013C730.
`AudList_LoadAudioFile__Fi` is a real named free function in AUDEDIT.CPP,
native lines1148..1164, loading `%s%02d.aud` directly into this pointer.
`AudList_PurgeAudio__Fv` frees it. Those names do **not** name the missing class
accessor, nor do their records identify its original header filename.

## Precise missing inline record

AudioTrk_PreLoad has the sole native CAudioList receiver record:

- `1bf4f2`: REG PTR STRUCT CAudioList, name `this`, physical register2/v0.
- Owning block `1bf4e9..1bf523`: **8007D410..8007D410**, relative caller line21.
- Nested empty block `1bf511..1bf51a`: same zero-width address span.
- SLD `1be751` maps that site to **AUDIOTRK.CPP line498**.
- The module's only SLD filename record is `1bde6d`, AUDIOTRK.CPP; no header
  filename switch appears within 8007C614..8007D5C4.

Raw words at D410..D41C are independently checked:
`3c028014 8c42c730 00009021 24510010` = load gGameAudioList into v0, initialize
i in s2, and form `se = v0 + 16` in s1. The native count load at D3D4 is
`lw s6,4(v1)` and belongs to caller line492, **not** this inline-this block.
Thus the inline site is associated with the trailing-element pointer, not the
earlier numElements_ count read.

The zero-width debug span does not prove an empty original method: optimized
inline expression computations/return setup can be outside its retained lexical
markers. `this` and the class tag establish receiver identity; they do not
establish the method's name, access level, qualifiers, return spelling or tokens.
Inventing GetData/GetElements/operator[] would exceed this evidence.

Reset has no native `se` or CAudioList `this` record (only its two i locals).
SoundTrack has a native `se`, but no CAudioList `this` record. PreLoad's receiver
record must not be used to bless Reset's inferred source pointer name. Existing
Reset index probes were read as prior failed evidence and were not repeated.
