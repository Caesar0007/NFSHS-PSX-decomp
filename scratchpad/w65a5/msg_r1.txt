LATENT DEFECT FIXED IN THE SAME COMMIT -- linkers/nfs4.ld `.nfs4`
SUBALIGN(16) -> SUBALIGN(4).  SUBALIGN forces EVERY input section in the
region to that alignment, so it silently pads between the blob PIECES the
ownership sweeps cut (front_data has been cut since W64-A18; piece boundaries
are 4-aligned, not 16).  With the rodata pieces added it stops being latent
and ld dies `final link failed: file truncated`.  Retail bases are 4-aligned
(catalog 14B) and the group boundaries that do need 16 are held by the
explicit `. = ALIGN(., 16);` statements.  P6 above is measured with the fix
held constant on BOTH sides, so the only variable is the cut.
